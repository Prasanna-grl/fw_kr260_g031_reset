01 Purpose

This guide explains how to program the STM32G031K8T6 reset controller with an approved .elf firmware file, using an STLINK-V3SET and the graphical interface of STM32CubeProgrammer.

02 Required items

STM32CubeProgrammer Use the approved production software package. Download software package
Reset-controller firmware fw_kr260_g031_reset.elf Download approved firmware
  • Production PC with an available USB port.
  • STLINK-V3SET with USB cable.
  • Approved programming cable, adapter, or production fixture.
  • Carrier card and its approved power supply. The Kria SOM is not required and must not be fitted during STM32 programming.
  • ESD-protected workstation and wrist strap.

03 Important safety and quality rules

Caution · ESDHandle the board only at an ESD-protected workstation.
Caution · WiringTurn target power off before connecting or disconnecting the programming cable. An offset or reversed connector may damage the target board or STLINK-V3SET.
Caution · Target powerThe STLINK-V3SET senses the target voltage through VTref; the production fixture must power the target board using its approved supply unless the fixture specification explicitly states otherwise. Do not assume the debug connector powers the board.
Caution · Option bytesDo not change Read Out Protection, write protection, boot configuration, or any other option byte unless a separate, approved production instruction explicitly requires it.

Use only the released .elf file identified in the work order and supplied through the approved firmware link.

05 Before programming

  1. Download the approved firmware package and save it to the controlled local production folder.
  2. Confirm the file name is exactly fw_kr260_g031_reset.elf.
  3. Verify its SHA-256 checksum against the value in the Document control table. If it does not match, stop and quarantine the file. Firmware revision 0.1 is not read back from the STM32; the approved file name and SHA-256 checksum identify the production firmware.
  4. Confirm that the Kria SOM is not installed. Only the carrier card is required for programming the reset controller.
  5. With carrier-card power off, connect the STLINK-V3SET to the target.
  6. Connect the STLINK-V3SET to the PC by USB.
  7. Apply the approved carrier-card power.

07 Program and verify the firmware

  1. Select the Erasing & Programming icon in the left toolbar (down-arrow symbol).
  2. In File path, select Browse and choose the approved fw_kr260_g031_reset.elf file.
  3. Reconfirm the complete file name and its folder before continuing.
  4. Set the programming options to the required states below.
OptionRequired state
Skip flash erase before programmingCleared
Verify programmingSelected
Run after programmingCleared
Full Flash memory checksumCleared unless required by the production traveler
Address handlingFor an .elf file, STM32CubeProgrammer obtains the programmed addresses from the file. Do not manually enter a start address.
  1. Select Start Programming.
  2. Do not remove power, unplug USB, move the fixture, or disconnect the cable while programming is in progress.
  3. Wait for both programming and verification to finish.
  4. Confirm the log reports successful download and verification with no red error messages. A download message without successful verification is not an acceptable production result.

08 Disconnect and perform the functional check

8.1 Prepare the assembly

  1. Select Disconnect in STM32CubeProgrammer.
  2. Turn carrier-card power off and allow the power rails to discharge.
  3. Disconnect the STLINK-V3SET programming fixture from the carrier card.
  4. Install the approved Kria SOM on the carrier card while power remains off.
  5. Connect the normal boot media, serial console, network cable, and other test equipment required by the production test station.

8.2 Verify power-on boot

  1. Capture the Kria boot console and apply normal product power.
  2. Using the programmed SD card, confirm that the Kria completes U-Boot and Linux startup.
  3. Confirm that the console reaches Reached target Login Prompts and automatic login.
  4. Record the power-on boot result as PASS.

8.3 Verify soft-reset boot

  1. Initiate the product's approved software reset while the system is running.
  2. Confirm that a new boot sequence appears on the console without manually cycling carrier-card power.
  3. Confirm that Linux again reaches Reached target Login Prompts and automatic login.
  4. Record the soft-reset boot result as PASS.

8.4 Verify QSPI firmware-update mode

  1. Use the product's approved control sequence to request QSPI firmware-update mode.
  2. Confirm that the console enters the recovery image and reports QSPI 32 bit Boot Mode.
  3. Confirm that the console reports Xilinx boot image recovery tool web server is running on port 80.
  4. Confirm that the firmware-update page is accessible at http://192.168.0.111 from the test PC configured on the same subnet.
  5. Record the QSPI firmware-update-mode result as PASS.

8.5 Complete the test

  1. Turn product power off after all three functional checks pass.
  2. Record the results in the production log.
  3. Apply the programmed/inspected label if required by the manufacturing plan.
Final acceptance criteria

The unit passes only when both conditions are met:

REQUIREDProgram & verifySTM32CubeProgrammer reports successful programming and verification.
REQUIREDFunctional testThe product-specific functional test passes.

09 Troubleshooting

SymptomOperator action
No ST-LINK detectedCheck the USB cable and PC connection. Confirm the STLINK-V3SET power/status indicators. Try the approved spare USB cable or probe.
No target voltageConfirm target power is on and VTref and GND are connected. Do not continue until the expected target voltage is present.
Cannot connect to targetTurn power off; reseat the fixture; inspect SWDIO, SWCLK, NRST, VTref, and GND; power on and retry once. If permitted by the station instruction, reduce SWD frequency to 4000 kHz and retry.
Wrong device or Flash sizeStop. Verify that the correct board is loaded and that the fixture is correctly aligned. Do not program the unit.
ELF file rejectedConfirm that the approved file was completely downloaded and has the expected .elf extension and SHA-256 checksum.
Programming or verification failsDo not mark the unit as passed. Power-cycle the target, inspect/reseat the fixture, and retry once. If it fails again, record the error and move the unit to the designated failure/quarantine area.
Functional test fails after programmingRepeat the functional test once according to its instruction. If it still fails, record the failure and quarantine the unit; do not repeatedly reprogram it unless authorized.
