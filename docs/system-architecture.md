# STM32G031K8 MPSoC Reset Controller System Architecture

## 1. Purpose

This firmware implements the MPSoC carrier reset-controller logic on an
STM32G031K8 target, using the NUCLEO-G031K8 pinout as the development reference
and a smaller STM32G0 device for the production board.

The design is ported from the earlier STM32G474 implementation, which itself
replaced the reset behavior originally implemented with an SLG7XL45106 /
SLG46880V GreenPAK device.

The G031K8 firmware currently implements:

- Debounced active-low reset-button handling.
- PS power-good qualified `SOM_PS_POR_B` generation.
- Delayed release of selected PS reset fan-out outputs.
- I2C slave compatibility for the GreenPAK virtual output register used to mask
  or release reset outputs.
- GPIO setup for PS, PL, power-good, reset-button, and I2C signals.

The current implementation is focused on the active PS reset behavior required
by the board. PL reset input pins are configured and available for future PL
logic, and `PL_RESET_IN4_B` is intentionally represented as a logical signal
derived from `CC_PL_PGOOD` instead of consuming another STM32G031K8 pin.

## 2. Hardware Platform

| Item | Current design |
| --- | --- |
| MCU | STM32G031K8Tx |
| Development board reference | NUCLEO-G031K8 / UM2591 |
| Firmware framework | STM32 HAL generated by STM32CubeMX |
| Build system | CMake project generated from CubeMX |
| System clock | HSI 16 MHz, no PLL |
| Reset timing source | HAL SysTick millisecond tick |
| I2C peripheral | I2C1 on PB8/PB9 |
| I2C role | Interrupt-driven slave/listen mode |
| Reset output type | Open-drain GPIO outputs |
| Build fit | About 16.2 KB flash and 1.7 KB RAM in Debug build |

The reset signals are active-low at board level. In firmware, a GPIO high level
means the reset net is released, and a GPIO low level means reset is asserted.

### 3.2 Reset Controller Application Layer

The reset-controller logic is implemented as static functions in
`Core/Src/main.c`.

| Function group | Functions |
| --- | --- |
| Debounce/service | `ResetController_InitDebounce`, `ResetController_Service`, `ResetController_HandleResetButtonInterrupt` |
| Output control | `ResetController_ApplyOutputs`, `ResetController_SetOpenDrainReset` |
| Input helpers | `ResetController_ReadPinHigh`, `ResetController_ResetButtonReleased`, `ResetController_PsPorReleased`, `ResetController_PsOutputsMayRelease` |
| I2C register model | `ResetController_ReadRegister`, `ResetController_WriteRegister`, `ResetController_NormalizeRegisterAddress`, `ResetController_BlockBaseFromAddress` |
| I2C lifecycle | `ResetController_StartI2CListen`, HAL I2C callbacks |

The main loop is intentionally simple:

```text
HAL_Init
SystemClock_Config
MX_GPIO_Init
MX_I2C1_Init
ResetController_InitDebounce
ResetController_ApplyOutputs
ResetController_StartI2CListen
Pulse SOM_PS_POR_B low for 25 ms
Forever: ResetController_Service
```

## 4. Pin Map

### 4.1 Inputs

| Signal | MCU pin | GPIO mode | Firmware use |
| --- | --- | --- | --- |
| `PS_RESET_IN1_B` | PA0 | Input, no pull | Qualifies `PS_RESET_OUT1_B` |
| `PS_RESET_IN2_B` | PA1 | Input, no pull | Qualifies `PS_RESET_OUT2_B` |
| `PL_RESET_IN1_B` | PA2 | Input, no pull | Configured, reserved for PL logic |
| `PL_RESET_IN2_B` | PA3 | Input, no pull | Configured, reserved for PL logic |
| `PL_RESET_IN3_B` | PA4 | Input, no pull | Configured, reserved for PL logic |
| `RESET_BUTTON_B` | PA6 | EXTI rising/falling, pull-up | Debounced active-low reset request input |
| `CC_PL_PGOOD` | PA8 | Input, pull-up | PL power-good; also logical source for `PL_RESET_IN4_B` |
| `CC_PS_PGOOD` | PC6 | Input, no pull | Qualifies `SOM_PS_POR_B` and PS reset-output release |

`PL_RESET_IN4_B` is not bonded to a separate STM32G031K8 pin. Its logical
release condition is:

```text
PL_RESET_IN4_B logical release = CC_PL_PGOOD high
```

| `PS_RESET_OUT2_B` | PB4 | Open-drain output | Released when PS release gate is true, `PS_RESET_IN2_B` is high, and I2C virtual bit 1 is set |

| `PS_RESET_OUT4_B` | PB6 | Open-drain output | Released when PS release gate is true and I2C virtual bit 3 is set |

### 4.3 I2C

| Signal | MCU pin | Peripheral |
| --- | --- | --- |
| `I2C1_SCL` | PB8 | I2C1 alternate function AF6, open-drain |

## 5. Reset Logic

### 5.1 Reset Button Debounce

`RESET_BUTTON_B` is active-low and uses the internal pull-up configured on PA6.
Firmware samples it in the main loop and also updates the raw sample timestamp
from the EXTI callback.

Debounce behavior:

```text
RESET_BUTTON_B raw sample changes
        |
        v
Record new sample and timestamp
        |
        v
If raw state remains changed for 25 ms
        |
        v
Accept as debounced reset-button state
```

| Constant | Value | Meaning |
| --- | --- | --- |
| `RESET_BUTTON_DEBOUNCE_MS` | 25 ms | Required stable time before accepting button state |
| `RESET_OUTPUT_RELEASE_DELAY_MS` | 25 ms | Delay after stable PS release conditions before fan-out reset outputs release |

### 5.2 SOM_PS_POR_B Generation

`SOM_PS_POR_B` is driven directly from the debounced reset button and PS
power-good status:

```text
SOM_PS_POR_B release =
    RESET_BUTTON_B debounced high
    AND CC_PS_PGOOD high
```

If either condition is false, the open-drain GPIO drives `SOM_PS_POR_B` low and
asserts PS POR.

During startup, the application explicitly holds `SOM_PS_POR_B` low for 25 ms
after I2C listen mode starts, then returns to normal reset-control logic.

### 5.3 PS Reset Output Release Gate

The common PS fan-out release gate is:

```text
PS outputs may release =
    CC_PS_PGOOD high
    AND SOM_PS_POR_B released high
    AND RESET_BUTTON_B debounced high
    AND release conditions have remained true for 25 ms
```

If any common condition becomes false, firmware immediately:

- Asserts all controlled PS reset outputs low.
- Marks a new 25 ms release delay as pending.

Once all common conditions return true, firmware waits until the 25 ms release
deadline before allowing individual outputs to release.

### 5.4 Individual PS Reset Outputs

Each controlled PS reset output is open-drain and released only when its local
conditions are true:

```text
PS_RESET_OUT1_B release =
    PS outputs may release
    AND PS_RESET_IN1_B high
    AND I2C virtual output bit 0 set

PS_RESET_OUT2_B release =
    PS outputs may release
    AND PS_RESET_IN2_B high
    AND I2C virtual output bit 1 set

PS_RESET_OUT3_B release =
    PS outputs may release
    AND I2C virtual output bit 2 set

PS_RESET_OUT4_B release =
    PS outputs may release
    AND I2C virtual output bit 3 set

PS_RESET_OUT7_B release =
    PS outputs may release
    AND I2C virtual output bit 6 set
```

Bits default high at boot through `SLG_VIRTUAL_OUT_DEFAULT = 0x7F`, so the I2C
mask starts in the reset-release-enabled state.

## 6. I2C Register Compatibility Model

The firmware exposes a small GreenPAK-compatible I2C slave register model for
virtual reset-output control.

| Property | Current firmware |
| --- | --- |
| Peripheral | I2C1 |
| Pins | PB8/PB9 |
| Addressing | 7-bit |
| Own address | CubeMX `.ioc` value `0x11`; generated `main.c` value `34`, the shifted STM32 HAL form for 7-bit address `0x11` |
| General call | Disabled |
| Clock timing | `0x00300617` |
| Analog filter | Enabled |
| Digital filter | Disabled |
| Interrupts | `I2C1_IRQn` enabled |

### 6.1 Supported Register

| Register | Alias | Access | Meaning |
| --- | --- | --- | --- |
| `0x01DB` | `0xDB` through block addressing | Read/write | Virtual output bit mask for selected reset outputs |

The virtual output register uses only bits `[6:0]`:

| Bit | Output controlled |
| --- | --- |
| bit 0 | `PS_RESET_OUT1_B` |
| bit 1 | `PS_RESET_OUT2_B` |
| bit 2 | `PS_RESET_OUT3_B` |
| bit 3 | `PS_RESET_OUT4_B` |
| bit 4 | Reserved |
| bit 5 | Reserved |
| bit 6 | `PS_RESET_OUT7_B` |

Any unsupported register read returns `0xFF`. Writes to unsupported registers
are ignored.

### 6.2 Address and Register Sequencing

The I2C callbacks implement single-byte sequential register access:

1. On slave address match for master write, the first received byte is treated
   as the register word address.
2. If the matched I2C address corresponds to the GreenPAK block-1 address,
   firmware ORs the received byte with `0x0100`.
3. Further received bytes are written to the selected register, with
   auto-increment after each byte.
4. On master read, firmware returns the current register value and
   auto-increments after each transmitted byte.
5. Listen mode is restarted after listen completion or I2C error.

`SLG_BASE_I2C_ADDRESS_7BIT` is `0x10`, and
`SLG_BLOCK1_I2C_ADDRESS_7BIT` is `0x11`. The current CubeMX/HAL own address
configuration listens on the block-1 address path used for register `0x01DB`.

## 7. Interrupt Architecture

| Interrupt | Handler | Role |
| --- | --- | --- |
| SysTick | `SysTick_Handler` | Increments HAL millisecond tick used for debounce and release delays |
| EXTI4_15 | `EXTI4_15_IRQHandler` | Dispatches PA6 reset-button edges to HAL EXTI |
| I2C1 | `I2C1_IRQHandler` | Dispatches I2C1 event or error handling |

All configured peripheral interrupts currently use priority `0,0`.

## 8. Power-On and Runtime Sequences

### 8.1 MCU Boot Sequence

```text
MCU reset
  |
  v
HAL and clock initialization
  |
  v
GPIO outputs default low:
  SOM_PS_POR_B = asserted
  PS_RESET_OUTx_B = asserted
  |
  v
GPIO inputs, EXTI, and I2C1 initialized
  |
  v
Debounce state initialized from current RESET_BUTTON_B level
  |
  v
I2C listen mode enabled
  |
  v
SOM_PS_POR_B forced low for 25 ms
  |
  v
Main loop continuously services debounce and reset outputs
```

### 8.2 Normal Release Sequence

```text
RESET_BUTTON_B debounced high
CC_PS_PGOOD high
SOM_PS_POR_B high
  |
  v
Wait 25 ms release delay
  |
  v
Release PS_RESET_OUT1_B if PS_RESET_IN1_B and VOUT0 are high
Release PS_RESET_OUT2_B if PS_RESET_IN2_B and VOUT1 are high
Release PS_RESET_OUT3_B if VOUT2 is high
Release PS_RESET_OUT4_B if VOUT3 is high
Release PS_RESET_OUT7_B if VOUT6 is high
```

### 8.3 Reset Button Press

```text
RESET_BUTTON_B goes low
  |
  v
After 25 ms debounce, button state is accepted as pressed
  |
  v
SOM_PS_POR_B driven low
PS release gate becomes false
  |
  v
All controlled PS_RESET_OUTx_B outputs driven low
```

When the button is released and remains high for 25 ms, `SOM_PS_POR_B` can
release if `CC_PS_PGOOD` is high. The PS reset outputs then wait for the
additional 25 ms output-release delay before release.

## 9. Implemented Versus Reserved Architecture

### Implemented Now

- PS POR generation using `RESET_BUTTON_B` and `CC_PS_PGOOD`.
- PS reset fan-out outputs 1, 2, 3, 4, and 7.
- I2C virtual-output control bits for those PS reset outputs.
- Debounce and release timing using HAL SysTick.
- I2C slave callback flow with register auto-increment.
- Logical `PL_RESET_IN4_B` derived from `CC_PL_PGOOD`.

### Configured or Reserved

- `CC_PL_PGOOD`.
- `PL_RESET_IN1_B` through `PL_RESET_IN3_B`.
- PL reset output fan-out.
- GreenPAK probe/status registers other than virtual output register `0x01DB`.
- Additional PS reset outputs 5 and 6.
- I2C primary address `0x10` as a simultaneously active own address.

## 10. Safety and Electrical Assumptions

- Reset outputs are configured open-drain to match board reset-net expectations
  and avoid actively driving externally pulled-up reset nets high.
- Internal pull-ups are not enabled on reset outputs.
- `RESET_BUTTON_B` uses an internal pull-up and active-low interpretation.
- `CC_PL_PGOOD` currently uses an internal pull-up in the CubeMX configuration.
  If the production board provides a strong external pull state, this can be
  changed to no-pull.
- Most reset and ready signals are interpreted as active-high release
  conditions despite `_B` net names, because high means the active-low reset net
  is not asserted.
- Any reset or power-good net with a possible pull-up above VDD must be
  level-shifted or otherwise made electrically valid for STM32G031K8 I/O.
- On the NUCLEO-G031K8 board, PC6 is also the user LED net. Using PC6 as
  `CC_PS_PGOOD` is acceptable for the production board if routed cleanly, but it
  may be loaded on the Nucleo board.
